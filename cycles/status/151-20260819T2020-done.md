# Ciclo 151 - done

## Resumo

Primeiro embed de COMPOSIÇÃO (os 3 anteriores são de banco de dados):
`{{ type: "callout" }}` — caixa colorida por variante (info/success/
warning/error/tip), com ícone, título editável, corpo markdown e
recolher/expandir.

Junto veio a peça reutilizável do ciclo: `EmbedMarkdownField`, o campo
de markdown editável dentro de um embed, que o ciclo 152 (columns)
reusa em cada painel.

## Arquivos criados/modificados

- `crates/core/src/embed.rs` — `EmbedKind::Callout`, `CalloutVariant`,
  `CalloutEmbedData`, parse tolerante de variante + 5 testes
- `crates/core/src/index.rs` — braço do novo tipo em `collect_embed_tags`
- `ui/src/components/embeds/markdown_field.rs` (novo)
- `ui/src/components/embeds/inline_callout.rs` (novo)
- `ui/src/components/embeds/mod.rs` — registro + braço do dispatcher
- `ui/src/components/icon.rs` — `info`, `alert-triangle`,
  `alert-circle`, `lightbulb`, `chevron-down`
- `ui/src/styles/main.css` — `.callout*` e `.embed-md*`

## Testes adicionados

- `callout_roundtrip_com_corpo_multilinha` (corpo com `:` e `#`)
- `callout_vazio_parseia_com_defaults`
- `callout_nao_serializa_collapsed_falso`
- `callout_variant_desconhecida_cai_no_default_sem_perder_o_resto`
- `callout_variant_slugs_batem_com_o_yaml`

## Problemas encontrados

- O plano previa `contenteditable` pro corpo. Seria reintroduzir o bug
  do ciclo 076 (texto duplicado dentro de contenteditable re-renderizado
  pelo Yew). Trocado por `<textarea>` na edição + HTML renderizado na
  leitura — mesma solução da célula Text da tabela.
- `variant` inválida derrubava a struct inteira (`unwrap_or_default`),
  o que apagaria título e corpo na primeira regravação. Deserialização
  própria, tolerante, com teste de regressão.

- O padrão "parse tolerante campo a campo" vale pra todo enum novo de
