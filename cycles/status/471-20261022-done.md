# 471 — As rotas do projeto no MCP

## O que mudou

- **`core::ferramentas::CONTRATO`** ganhou quatro ferramentas:
  - `ver_projeto([projeto])` só lê. Sem `projeto`, lista os projetos e
    devolve o `MODELO_DE_PLANO` e o "como montar". É assim que uma LLM
    conectada só por MCP, sem shell pro CLI, descobre o formato.
  - `propor_plano_de_projeto(plano, [motivo])`.
  - `propor_sprint(projeto, nome, [objetivo], [inicio], [fim])`.
  - `propor_tarefa(projeto, titulo, [corpo], [sprint], [lote])`.
- A invariante do ciclo 204 segue no teste: as cinco que escrevem se
  chamam `propor*` e declaram revisão humana.
- **`crates/cli/src/mcp.rs`:** os quatro ramos chamam os mesmos
  `handle_*` do 470, com autor `mcp`. A resposta das que propõem diz
  "NADA foi gravado" ou "NÃO foi gravada", e o plano errado volta com
  `isError` e o nome do campo.
- **`como_agir`:** pra montar um projeto, não escrever as páginas na mão,
  e sim usar `ver_projeto()` → `propor_plano_de_projeto` (ou o CLI).
- **Semente:** o prompt padrão `montar-a-base-do-projeto.md`, também
  proposto no `VaultAnotadinho`
  (`pages-prompts-default-montar-a-base-do-projeto-md-1792712696`),
  porque a semente só vale pra vault novo.
- **TUI:** o modal de escolha cresce até caber o item mais longo, com a
  tela como teto.

## O que apareceu

O teste da tela de ferramentas da TUI (`a_tela_mostra_o_contrato_de_ferramentas`)
reprovou. Primeiro, porque 15 ferramentas não cabiam em 24 linhas; isso
era só a altura do teste, porque a lista rola. Depois, com 40 linhas,
reprovou de NOVO pelo motivo de verdade: o modal tinha 56 colunas fixas,
e as assinaturas das ferramentas novas saíam cortadas com "…". Quem lia
a tela não via os parâmetros. Corrigido no modal, sem nenhuma foto de
tela alterada.

## Como foi verificado

- Core: o contrato (5 testes) e a semente (o prompt novo é descoberto).
- CLI: 2 testes de integração novos pelo PROTOCOLO MCP.
  - `ver_projeto()` → modelo → `propor_plano_de_projeto` (7 propostas,
    nada gravado) → aplicar → `ver_projeto("agenda")` (2 sprints) →
    `propor_tarefa` na sprint "Agendamento" (aplicada, `sprint: 2`) →
    `propor_sprint`;
  - o plano errado volta `isError` com o nome do campo.
- `toda_ferramenta_publicada_tem_quem_atenda` passa com as 15.
- `cargo test --workspace` verde. `cargo check` no alvo Windows ok para o
  CLI e a TUI, `trunk build` e o build do Tauri ok.
