# Ciclo 137 - done

## Resumo

Bug real reportado pelo usuário: nenhum atalho global funcionava
antes do primeiro clique dentro do app — foco começa em `<body>`, e
eventos de teclado só borbulham pra cima, nunca alcançando o
`onkeydown` de `.app-root`. Corrigido focando `.app-root`
programaticamente uma vez, no mount. Achado colateral: isso ativava
um contorno azul ao redor da janela inteira (heurística de
`:focus-visible` do WebKitGTK) — suprimido com uma regra CSS mais
específica.

## Arquivos criados/modificados

- `ui/src/app.rs` — `app_root_ref` + foco no mount
- `ui/src/styles/main.css` — `.app-root:focus-visible { outline: none; }`

## Testes

`cd ui && cargo test --lib`: 84. `cargo test --workspace`: 116.
`trunk build` + `cargo build --manifest-path src-tauri/Cargo.toml`: OK.

Validação ao vivo via MCP `tauri`: reproduzido o bug exatamente como o
usuário descreveu (reload, sem clicar em nada, Ctrl+R não fazia
nada); confirmado corrigido no mesmo cenário; confirmado sem contorno
visível ao redor da janela depois do fix de CSS.

## Notas

Ver Notas no arquivo de task: retrospectiva reconhecendo que notas de
ciclos anteriores (123-136) caracterizaram erroneamente a necessidade
de focar `.app-root` antes de testar como um detalhe só do driver de
automação MCP — na verdade é um bug real do app que só não tinha sido
notado em uso normal porque o usuário costuma clicar em algo antes de
usar um atalho.
