# 489 — Construtor mermaid: formulários de sequência e gantt — done

## O que foi feito

- `ui/src/components/construtor_mermaid/linhas.rs`: as peças comuns.
  - `AcaoLinha` e `aplicar`: subir, descer e apagar numa lista;
  - os botões da linha, com o motivo quando o apagar está bloqueado;
  - `com`: um callback que edita uma cópia do modelo e a emite;
  - `CampoData`: o `DatePicker` do app atrás de um botão.
- `sequencia.rs`: `EditorSequencia`.
  - Os participantes ganham id automático (`P1`, `P2`…), e nome vazio
    volta a ser o id (`participant P1 as` sem nome não é mermaid). O
    participante citado não se apaga.
  - Dois alvos de nota só existem em "sobre": trocar o lado corta o
    segundo.
- `gantt.rs`: `EditorGantt`.
  - **Dependência:** a lista mostra as tarefas pelo nome. Escolher uma sem
    id dá um id novo a ela (`t1`…). Só entram tarefas com início escrito,
    porque o mermaid não aceita `id, duração`. Pela mesma regra, escolher
    "logo depois da anterior" tira o id, e o campo de id fica desabilitado.
  - **Duração e id** só entram no modelo quando válidos. No meio da
    digitação, o diagrama fica como estava.
  - **Marcas** saem sempre na ordem do mermaid, então marcar em outra ordem
    não muda o código.
  - Apagar uma seção com tarefas, ou uma tarefa de que outra depende, fica
    bloqueado.
- `mod.rs`:
  - **o "Aplicar" lê o código por `use_mut_ref`.** Com o `use_state`
    capturado, a edição feita logo antes do clique, sem render no meio, se
    perdia;
  - a aba Construtor mostra os editores de sequência e gantt. Fluxograma e
    estados ficam com o resumo até o 490.
- `ui/src/styles/components.css`: o formulário, só com tokens.

- `cd ui && cargo test --lib` (67) e `trunk build` passaram.
- Os três cenários 489, no app de desenvolvimento:
  - **sequência:** o nome com `;` aparece escapado no código e certo na
    prévia; a mensagem nova vira resposta e sobe uma posição; apagar um
    participante citado está desabilitado; e o arquivo fica com
    exatamente o código do construtor;

    como `crit`. A prévia não mostra erro;
  - **"Aplicar" logo depois de digitar:** o input e o clique vão na mesma
    chamada síncrona. **Visto reprovando** com o `aplicar` lendo o
    `use_state`: veio `A --> B` no lugar de `A --> Ultima`.

  construtor, o `Escape` fecha só o seletor.
