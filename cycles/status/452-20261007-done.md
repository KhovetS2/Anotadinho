# 452 — A Visualização é a tela final

## O que estava errado (medido na janela)

A Visualização chamava o mesmo `markdown_render::render` do editor, mas
fora de `.editor__wysiwyg` e sem os passos que o editor aplica depois.
O CSS de página mora todo em `.editor__wysiwyg …` e `.editor__bloco`,
e nada dele chegava ali:

| | Visualização | Editor |
|---|---|---|
| texto | 16px / 24px | 15px / 25,5px |
| `h2` | 700, margem 0 | 600, 16px acima |
| parágrafo | margem 0 | 8px abaixo |
| lista | recuo 0 | recuo 24px |
| `code` | sem fundo | fundo |
| negrito | cor do texto | cor de destaque |

Imagem do vault, transclusão, realce e mermaid também não rodavam. E a
Visualização mostrava `p.conteudo` inteiro mesmo com trechos tirados.

## O que mudou

- `editor::preparar_leitura`: o pipeline do efeito de render do editor,
  na mesma ordem, sem `contenteditable`, `tabindex` e navegação.
  `marcar_blocos_leitura` põe só as classes, com a regra da lista como
  grupo (`e_grupo`, agora uma função usada pelos dois).
- `PaginaPreview` monta a árvore do editor e preenche cada trecho por
  `set_inner_html`, com a chave tipo+contagem do ciclo 079.
- A revisão passa o conteúdo parcial pra Visualização.
- `.propostas__l`: `pre-wrap` + `overflow-wrap: anywhere`.
